# jav-dl 下一阶段

个人局域网控制台（约 2.0）已能检索、下磁链、归档和追更。这一阶段补刮削落盘、换源删除、欧美文件名确认、浏览筛选进 hash、追更可见性。

历史阶段 1–10 在 `docs/prd.md`，视为已完成，不在这里重排。

## 已有基线

- 栈：Python 3.12+ / FastAPI，静态 SPA（`app/static/`，hash 路由），SQLite，aria2 或迅雷。元数据来自 JavBus、ThePornDB、磁力猫。
- 已有：JAV / 欧美浏览与搜索；磁链排序；下载队列（入队、暂停、继续、取消、批量、选文件、SSE）；刮削归档与媒体库；追更与通知；设置与可选 HTTP Basic；播放器片库 API。
- 追更保持：默认只提醒；自动下载单独开；可按 UC、中字、体积过滤；库里已有或已标 suck 的不重复入队。
- 和本阶段相关的现状：
  - `write_images` 把同一张封面字节写入 `poster.jpg` 和 `fanart.jpg`。详情样图已解析，归档时丢弃。NFO 演员只有名字和 `type`，页面上的头像 URL 没写入。
  - 媒体库卡片演员是纯文本。`library` 表已有 `studio`、`series`，页面接口没带回。
  - Hash 只区分 JAV、欧美、媒体库、追更、队列、设置。有码/无码、平面/VR、页码、主题不在 hash 里。
  - 队列「删除」只删记录。库内「标 suck」会删文件并禁止再下。没有「只删当前版本、允许换源再下」。
  - 欧美文件名对不上时只记日志并稍后重试，页面上没有候选可选。
  - 关注卡不显示已记下的部数。女优要手填站名。追更里的欧美新作不能点进详情。

## 本阶段将做

- A1. JAV 封面：`fanart.jpg` 为完整横版原图；`poster.jpg` 为从右侧裁出的 2:3。
- A2. 详情已抓到的预览图写入 `extrafanart/`，归档时不再丢弃。
- A3. NFO 演员条目写入页面上已有的头像 URL。
- B1. 番号平面最新列表增加常见类型芯片，复用 JavBus 类型页。
- B2. 媒体库用 NFO 里的演员、片商、系列做可点筛选。
- B3. 封面在固定比例上加一档疏、一档密，不要缩放滑条。
- B4 / E2. 有码、平面、页码及其他筛选写入同一套 hash。刷新和分享不丢。
- C1. 磁链行展示排序理由，例如 `UC · 热度 320 · 6.2 GB`。
- C2. 队列标题点回对应番号或欧美详情。
- C3. 欧美刮削文件名对不上时留在待确认区，提供若干 ThePornDB 候选供点选。
- D1. 关注卡显示「已记下 N 部」。
- D2. 详情和女优目录一键「关注此女优」，带入站上名字和 star URL。
- D3. 追更新作列表里的欧美条目可点进详情。
- D4. 「暂无符合规则的磁链」写明后端还会再试。
- E1. 单纯删除当前归档版本，删掉后可换源重下。与「重新刮削」和「标 suck」分开。

## 明确不做

- 字幕翻译、字幕下载、页内播放、悬停预览、进度条 scrubber。
- 下载或缓存演员头像，建头像目录、头像墙、本地头像匹配。NFO 里的 URL 到此为止。
- 脸检测，以及无码/素人单独裁切策略。裁切函数可留扩展点，本阶段不调用。
- 第二刮削源，JavSP / MDCx 多站回退，ThePornDB 以外的欧美元数据站。
- 改磁链排序、改追更默认值、改「库里已有仍可手动下、suck 才禁止入队」。
- 为类型芯片逐卡请求详情，或抓取 JavBus 全部分类做索引。
- 批量重做旧库海报。旧片要新封面时，对那一部点重新刮削。
- 媒体库筛选跳到 JavBus 关键字搜索。库内 NFO 没有 star URL。
- 一键关注系列、片商、欧美演员。需要时仍用追更页手填。
- 删除时顺带写 suck，或把队列「删除记录」改成删文件。
- 欧美 `extrafanart`、欧美右裁海报、把横版 fanart 写进欧美平面目录。
- 播放器协议变更。JAVPlayer 继续读现有片库 API。

## 执行假设

信息不足处按下面执行，不单独停下来问。范围若要改，先改本文件。

1. A1–A3 只改 JAV 平面和番号 VR（二者已共用 `write_images` / `build_nfo`）。欧美继续用 ThePornDB 的 `posters.large` 写 `{stem}-poster.jpg`，不右裁，不建 `extrafanart/`。
2. 右裁对全部 JAV 封面统一执行，含无码。
3. 新规则用于新归档，以及用户点「重新刮削」时重写侧车文件。不批量改已入库旧海报。被动补缺（`fill_jav_folder`）仍只在文件缺失时写入。
4. `fanart.jpg` 保存横版原图字节，不重新编码。原图宽于 2:3 时，`poster.jpg` 从右缘裁一块 2:3。已更窄或裁切失败时，海报退回整图拷贝，归档不因此失败。
5. 预览图用 `samples[].full`，写入 `extrafanart/fanart-01.jpg` 起。单张失败跳过，上限 20 张。不进 `data/img_cache`。
6. 头像只写 NFO `<actor><thumb>`，用已解析的 `actors[].photo`。库索引仍然只存演员名字。
7. 类型芯片只加在平面最新列表，复用 `/api/jav/browse`。VR 仍走现有 VR専用（`genre/7x`、`uncensored/genre/gre162`）。芯片先固定：中出、巨乳、熟女、制服、单体、痴女、多P、OL。有码和无码用各自的 genre 路径。实现时用当前 JavBus 域名核对路径。不对每张卡片抓类型。
8. 媒体库筛选在已加载的 `/api/library` 上做。点演员名是在库内筛这个人的片子。片商、系列同样。不把全部演员铺成芯片墙。
9. 疏密两档。JAV 墙和番号库卡保持 2:3，欧美库卡保持 16:9。默认档等于现在的 `minmax(150px)`。没有滑条。
10. Hash 是唯一筛选状态：`#/jav?...`、`#/western?...`、`#/library?...`。队列、追更、设置仍是 `#/queue`、`#/follow`、`#/settings`。目录墙的 browse URL、打开中的番号或 ThePornDB id 也写进这套参数。不用第二份 localStorage。
11. 磁链理由只改展示。排序函数不动。欧美没有 UC 标签时不编造，写热度和体积。
12. 队列标题：能规范成番号的进 JAV 详情；sidecar 里有 `tpdb_id` 的进欧美详情。对不上的保持纯文本。
13. C3 只在 `fetch_by_filename` 失败或 `choose_match` 打平时出现。自信命中仍自动归档。候选最多 8 条，来自现有 parse / 日期标题搜索。待确认写入 SQLite。确认前该文件不再每 5 分钟打 ThePornDB。队列任务和没有队列行的监控文件进同一块「待确认」。
14. 「已记下 N 部」等于该订阅在 `subscription_seen` 的行数。关注规则不变。
15. 一键关注只做 JAV 女优，默认只提醒。同一 target 已存在则显示已关注，不建第二条。
16. 追更欧美条目的 `code` 已是 ThePornDB id。订阅侧不区分 scene/movie 时先按 scene 打开，404 再试 movie。
17. D4 只改文案，写明 14 天内还会再试（与 `FOLLOW_RETRY_FOR` 一致）。重试逻辑不改。
18. 「删除此版本」走已有 `remove_archived`，并删掉对应库行。不写 suck，不碰 `plays`。确认框写明文件会被删掉。

## 里程碑

顺序：M1 刮削画面 → M2 磁链与换源删除 → M3 欧美待确认 → M4 浏览和 hash → M5 追更。C3 单独成里程碑，因为它要新表和新确认界面，不是小改，且排在浏览之前：卡住的欧美文件比封面密度更影响入库。

### M1 刮削画面

- 目标：新归档的 JAV 目录有可用的 fanart、右裁 poster、预览图和带 thumb 的 NFO。
- 需求：A1、A2、A3。任务：M1-T1 至 M1-T4。
- 依赖：无。不改下载器，不改欧美归档。
- 验收：
  - 横版封面归档或重新刮削后，`fanart.jpg` 与原图字节一致；`poster.jpg` 宽高比约 2:3，内容取自原图右侧。
  - 详情有样图时 `extrafanart/` 有对应文件。某张下载失败时，视频和 NFO 仍然落盘。
  - 有 `photo` 的演员 NFO 含 `<thumb>`。没有新的本地头像文件。
  - 竖图或裁切失败时海报等于整图，任务仍为已归档。
  - `.venv/bin/python -m pytest` 通过，至少覆盖 `tests/test_nfo.py`、`tests/test_scrape.py`。
- 风险：主体在左侧的封面会被裁错，本阶段接受。样图不要进入封面缓存。旧库看起来不变，直到对单部重新刮削。回滚是恢复「两份同一张图」。

### M2 磁链理由、回详情、换源删除

- 目标：看懂磁链为何靠前；从队列回到作品；删掉已归档版本后能下另一条。
- 需求：C1、C2、E1。任务：M2-T1 至 M2-T3。
- 依赖：无代码依赖 M1。演示「重新刮削会重写新侧车」时，M1 已完成更清楚。
- 验收：
  - JAV 磁链行能读到 `UC · 热度 n · 体积` 这类理由。排序仍是无码破解 > 无码 > 中文 > 热度 > 体积。欧美行不出现凭空的 UC。
  - 队列番号标题打开该番号详情。带 sidecar 的欧美任务打开欧美详情。
  - 「删除此版本」后，番号目录或欧美视频及同名 nfo/poster 消失，库行消失，suck 表没有这条，同一作品可以再次入队。
  - 「重新刮削」仍只重试刮削。「标 suck」仍会拉黑。
  - 删除路径越界失败，与现有 `remove_archived` 一致。
- 风险：删除不可恢复。文案不能沿用队列「删除记录、文件不动」。回滚可先拿掉按钮。

### M3 欧美文件名待确认

- 目标：自动对不上的欧美文件停在可见列表，点一条 ThePornDB 结果后沿现有归档写入片商目录。
- 需求：C3。任务：M3-T1 至 M3-T3。
- 依赖：M2 的队列页可以一起放「待确认」，接口不依赖删除。
- 验收：
  - 文件名能唯一命中时仍自动归档。
  - 打平或没有命中时，队列页「待确认」出现该文件和候选（标题、片商、日期、演员）。点一条后写入欧美库，待确认记录消失。
  - 重启后待确认还在。确认前不会因这个文件周期请求 ThePornDB。
  - 没有「全部采纳第一条」之类的批量自动提交。
- 风险：选错会进错误片商目录。回滚是停用确认接口，监控恢复旧重试；已归档文件用 M2 的删除去掉。

### M4 浏览手感和 hash

- 目标：最新列表和媒体库的筛选在刷新、复制链接之后还在。
- 需求：B1、B2、B3、B4、E2。任务：M4-T1 至 M4-T4。
- 依赖：无后端依赖 M1–M3。hash 解析先于芯片、库筛选和疏密，避免两套状态。
- 验收：
  - 平面最新有类型芯片，可翻页；「最新」回到未筛选列表。VR 仍是 VR専用，不叠这组芯片。
  - 媒体库点演员、片商、系列后只剩对应条目，可清除。欧美库没有系列筛选。关键字框仍可用。
  - 疏、密切换后比例不变。默认看起来和现在一致。没有滑条。
  - 复制带筛选的 hash，刷新后停在同一视图。队列、追更、设置不受影响。
  - 详情里点女优、系列、片商、类型仍打开目录墙，且 browse 写在 hash 里。
- 风险：现有详情 `pushState` 不改 hash，容易和 `hashchange` 双触发。只保留 hash 为源。类型 id 失效时沿用现有 browse 错误提示。

### M5 追更可见性

- 目标：看清已记下多少、少打字关注女优、欧美新作能点开、没磁链的状态读得懂。
- 需求：D1、D2、D3、D4。任务：M5-T1 至 M5-T4。
- 依赖：D3 在 M4 已完成时走同一套 hash；未完成时也可直接打开现有详情。
- 验收：
  - 每张关注卡显示「已记下 N 部」，N 等于 `subscription_seen` 行数。新建后的「已记下当前 N 部」仍然出现。
  - 「关注此女优」用页面上的名字和 star URL 创建订阅，默认只提醒。重复点击不产生第二条。按钮上没有自动下载开关。
  - 欧美新作点进 ThePornDB 详情。JAV 番号链接保持现有行为。
  - `no_magnet` 的行能读到还会在 14 天内再试。入队后状态仍变为「已入队」。
- 风险：一键关注会立刻跑现有的首次检查。按钮要防连点和重复 target。

## 文档驱动约定

开干前读本目录三份：`prd.md`（范围和验收）、`task.md`（任务状态）、`status.md`（当前做到哪）。

选下一条任务：

1. `status.md` 里已有 `doing` 时，继续那一条，不另开。
2. 没有 `doing` 时，只在当前里程碑里选：状态为 `todo`、依赖任务全部为 `done`、优先级 P0 优先于 P1。同优先级按任务 ID 顺序。
3. 当前里程碑没有可做任务时，才进入下一个里程碑，仍按第 2 步选。
4. 一次只把 1 条任务标为 `doing`，并写入 `status.md`。
5. 完成时：`task.md` 改为 `done`，`status.md` 的完成摘要加一行做了什么。
6. 受阻时：标 `blocked` 并写清原因，然后按第 2–3 步另选一条可做的 P0 或 P1。不跳过仍可做的当前里程碑 P0。
7. 范围、验收、不做清单变了才改 `prd.md`。纯进度不改本文件。

状态只允许 `todo`、`doing`、`done`、`blocked`。本阶段没有 P2 任务。

UI 任务完成前在浏览器里点过该任务的路径。每个里程碑收口前跑 `.venv/bin/python -m pytest`。改了静态文件时递增 `index.html` 里的 `app.js` / `style.css` 版本参数。
