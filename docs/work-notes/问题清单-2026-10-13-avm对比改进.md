## 3. 问题明细

### 3.1 中

#### QL-001 日期番号带厂牌前缀时解析出两个番号，监控不归档

- **处理**：可修
- **位置**：`app/codes.py:98`、`app/codes.py:117`、`app/scrape.py:309`
- **现象**：`extract_codes("carib-010120-001")` 返回 `['010120-001', 'CARIB-01012']`，`extract_codes("1pondo_010120_001")` 返回 `['010120-001', 'PONDO-01012']`。`extract_code` 只在恰好一个番号时返回，于是这两类文件得到 `None`。
- **根因**：`CODE_HYPHEN_RE` 的匹配没有排除已被 `DATE_HYPHEN_RE` 占用的区间（只排除了 FC2 和 VR 区间），且数字段后没有 `(?!\d)`，从 `010120` 里截出了 `01012`。
- **影响**：下载目录监控（`list_ready_sources`）认不出这类文件，迅雷面板里直接下的加勒比、一本道、天然むすめ等不会被归档，一直留在下载目录。
- **建议**：`extract_codes` 记录日期番号的 span，`CODE_HYPHEN_RE` 和后续 loose 匹配跳过与日期 span 重叠的结果；`CODE_HYPHEN_RE` 数字段后加 `(?!\d)`。在 `tests/test_codes.py` 补用例：`carib-010120-001`、`1pondo_010120_001`、`010120_001-1pon` 都只得到 `010120-001`，`extract_code` 返回它；原有用例不变。

#### QL-002 种子名里的中字、破解标记在归档改名后丢失

- **处理**：可修
- **位置**：`app/scrape.py:598`、`app/scrape.py:329`、`app/scrape.py:724`、`app/library.py:148`、`app/library.py:249`
- **现象**：归档时 `assign_video_names` 把视频改名为 `{番号}.ext`。`index_code_dir` 调 `release_flags` 时只传目录名、改名后的视频名和 NFO 名，原来种子名、目录名里的 `-C`、`-UC`、`中文字幕`、`破解`、`流出` 都已经不在了。NFO 的 genre 来自 JavBus，通常不含「中文字幕」「破解」。
- **影响**：媒体库和 `/api/player` 的 `has_sub`、`has_cracked` 基本只能为 0，按中字、破解筛选失效。下载时明明按 UC / 中字选了磁链，入库后看不出来。
- **建议**：归档前从原始名字识别标记并写进 NFO 标签，重新刮削时保留。分四步：
  1. 在 `app/library.py` 抽一个从名字识别标记的函数（参考 avm `app/parser.py` 的 `detect_flags`）：中字认 `中文字幕`、`中字`、带分隔符的 `-C` / `-CH` / `-UC` / `_C`、紧贴数字的 `CH` / `C` / `UC`（如 `IRO061C`、`SONE-760CH`）、`CHS` / `CHT` / `CHSUB`；破解认 `破解`、`流出`、`uncensored`、`無修正`、`无修正`、`-U` / `-UC` 后缀。`release_flags` 改用这个函数，原有判断（genre 含「中文字幕」「破解」等）保留。
  2. `scrape_job` 在搬文件前，用任务的 `title`（磁链标题，可能为空）、来源路径名、原视频文件名识别标记，命中时在传给 `build_nfo` 的 meta 的 genres 里追加 `中文字幕`、`破解`（已有则不重复）。这样改名后 `release_flags` 仍能从 NFO 读到。
  3. `refresh_jav_sidecars`（重新刮削）重写 NFO 前读出旧 NFO 里的 `中文字幕`、`破解` 标签并带到新 NFO，不能因重新刮削丢标记。`fill_jav_folder` 只在 NFO 缺失时写，不需要改。
  4. 测试：`tests/test_library.py` 覆盖各种写法的识别；`tests/test_scrape.py` 覆盖源名带 `-C` / `-UC` 的归档后 `has_sub` / `has_cracked` 为 1，以及重新刮削后标记仍在。

#### QL-003 JavBus 验证页被报成「未找到该番号」

- **处理**：可修
- **位置**：`app/sources/javbus.py:94`、`app/sources/javbus.py:303`、`app/sources/javbus.py:389`
- **现象**：`parse_javbus` 只识别 `#ageVerify`。JavBus 跳到 driver-verify 页或返回 Cloudflare 挑战页（HTTP 200、没有 `h3`）时，抛 `MetadataError("未找到该番号")`。`fetch_metadata` 还会接着试 `/uncensored/{code}`，最终报的仍是「未找到」。
- **影响**：被拦截时，队列里的刮削失败原因、详情页报错都说片子不存在，用户无从判断该换代理还是确实没有。
- **建议**：在 `app/sources/javbus.py` 加一个识别拦截页的函数（参考 avm `app/providers/base.py` 的 `detect_blocker`）：最终 URL 含 `driver-verify`，或正文含 `driver-verify`、`challenge-platform`、`cf-browser-verification`、`Just a moment`、`Enable JavaScript and cookies` 时判为拦截。`fetch_metadata`、`fetch_javbus_html`、`fetch_latest`、`search_works` 拿到 2xx 响应后先检查，命中就抛 `MetadataError("JavBus 返回了验证页，不是没有这部片。换代理或稍后再试", 503)`；`fetch_metadata` 遇到拦截立即抛出，不再试下一个路径。状态码不能用 404，`app/routers/search.py:72`、`app/routers/search.py:157`、`app/follow.py:182` 会把 404 当成「没有结果」。在 `tests/test_javbus_parse.py` 用内联 HTML 覆盖 driver-verify、Cloudflare 两种页面和正常详情页。

#### QL-004 数字前缀素人番号丢前缀，规范化也不认

- **处理**：可修
- **位置**：`app/codes.py:5`、`app/codes.py:47`、`app/codes.py:98`
- **现象**：`extract_codes("259LUXU-1234")` 得到 `LUXU-1234`，`300MAAN-123`、`200GANA-2000` 同理丢掉数字前缀。`normalize_code("259LUXU-1234")` 返回 `None`，搜索框里输入它会被当成关键词。
- **影响**：MGS 素人片在 JavBus 上的番号带数字前缀，丢前缀后按 `LUXU-1234` 查详情会失败，监控归档和批量粘贴都会刮削失败。
- **建议**：新增数字前缀规则：`(?<![A-Z0-9])(\d{3}[A-Z]{2,6})-?(\d{3,5})(?!\d)`，格式化为 `259LUXU-1234`。`normalize_code` 在 `CODE_RE` 之前接受 `^(\d{3}[A-Z]{2,6})-?(\d{3,5})$`；`extract_codes` 在 `CODE_HYPHEN_RE` 之前匹配，并让后续规则跳过它的 span。字母部分在 `FALSE_PREFIXES` 里的不算。确认 `code_maker("259LUXU-1234")` 为 `259LUXU`、`jav_vr_maker` 返回 `None`，日期番号、FC2、VR 用例不受影响。在 `tests/test_codes.py` 补用例。

### 3.2 低

#### QL-005 `heyzo_hd_2345` 解析成 `YZOHD-2345`

- **处理**：可修
- **位置**：`app/codes.py:47`、`app/codes.py:133`
- **现象**：`extract_codes("heyzo_hd_2345")` 返回 `['YZOHD-2345']`。`HD` 在 `FALSE_PREFIXES` 里被跳过后，loose 规则在压缩串 `HEYZOHD2345` 里截出了 `YZOHD`。
- **影响**：HEYZO 带 `hd` 段的文件得到错误番号，刮削失败。
- **建议**：加 HEYZO 专用规则 `HEYZO[-_ ]*(?:HD[-_ ]*)?(\d{4})(?!\d)` → `HEYZO-{4位}`，`normalize_code` 和 `extract_codes` 都在通用规则之前匹配。补用例 `heyzo_hd_2345`、`HEYZO-1234`、`heyzo1234`。

#### QL-006 `XXX-AV-12345` 解析成 `AV-12345`

- **处理**：可修
- **位置**：`app/codes.py:47`、`app/codes.py:98`
- **现象**：`extract_codes("XXX-AV-12345")` 返回 `['AV-12345']`，`normalize_code` 返回 `None`。
- **影响**：XXX-AV 系列查不到详情。
- **建议**：加专用规则 `XXX-?AV-?(\d{4,5})(?!\d)` → `XXX-AV-{编号}`，在通用规则之前匹配并占用 span。补用例。

#### QL-007 DMM 补零写法 `ssis00123` 规范成 `SSIS-00123`

- **处理**：可修
- **位置**：`app/codes.py:5`、`app/codes.py:47`、`app/codes.py:133`
- **现象**：`normalize_code("ssis00123")` 和 `extract_codes("ssis00123")` 都得到 `SSIS-00123`。DMM 内容 ID 把编号补零到 5 位，JavBus 番号是 `SSIS-123`。
- **影响**：直接贴 DMM 内容 ID 或用它命名的文件查不到详情。
- **建议**：字母厂牌番号（普通和 VR，不含 FC2、日期番号、QL-004 的数字前缀番号）编号为 5 位且以 `00` 开头时，去掉前两个 0 保留 3 位。补用例 `ssis00123` → `SSIS-123`、`SSIS-00123` → `SSIS-123`、`dsvr00123` → `DSVR-123`，`SIRO-4567`、`HEYZO-0123` 不变。

#### QL-008 JavBus 占位头像写进 NFO 的 thumb

- **处理**：可修
- **位置**：`app/nfo.py:69`
- **现象**：JavBus 对没有照片的女优用占位图 `nowprinting.gif`。`build_nfo` 把 `actors[].photo` 原样写进 `<thumb>`。
- **影响**：Emby / Jellyfin 等读取 NFO 时把占位图当成女优头像。
- **建议**：`build_nfo` 写 thumb 前，URL 的文件名含 `nowprinting` 时不写 `<thumb>`。不改 `parse_javbus` 的输出，页面显示保持现状。在 `tests/test_nfo.py` 补用例。

#### QL-009 用 gfriends 补女优头像 URL

- **处理**：待确认
- **位置**：`app/nfo.py:69`、`app/sources/javbus.py:120`
- **现象**：JavBus 没有照片的女优，NFO 里没有可用头像。avm 的 `app/plugins/gfriends.py` 从 gfriends 仓库的 `Filetree.json`（几 MB，经 jsDelivr / GitHub）按名字找到头像 CDN 地址。
- **影响**：不做的话，这部分女优在媒体服务器里没有头像。
- **建议**：拍板后的做法：经 `site_client` 拉取 `Filetree.json`，缓存到 `data/` 并设 TTL（如 7 天），失败短时间内不重试；`photo` 为空或为占位图时按名字精确匹配、去空格匹配，命中后只把 CDN URL 写进 `<thumb>`，不下载图片。
- **待确认**：由用户决定是否接受新增对 GitHub / jsDelivr 的外部依赖；`docs/prds/jav-dl-next/prd.md` 写过「不做本地头像匹配」，按名字匹配远程头像是否算在内。

#### QL-010 JavDB 作为 JavBus 查不到时的第二元数据源

- **处理**：待确认
- **位置**：`app/sources/javbus.py:389`、`app/scrape.py:384`
- **现象**：JAV 元数据只有 JavBus（FC2 走官方页）。JavBus 没收录或被拦截时直接刮削失败。avm 用多源调度：第一个命中的源作主，后续源只补空字段，列表字段取并集。
- **影响**：JavBus 没有的作品无法归档。
- **建议**：拍板后的做法：新增 `app/sources/javdb.py`（搜索 `/search?q={code}&f=all` → 详情 `/v/{id}`），设置页加 JavDB 地址和 Cookie；`resolve_metadata` 在 JavBus 返回 404 时才回退 JavDB，被拦截（QL-003）时不回退。
- **待确认**：`docs/prds/jav-dl-next/prd.md` 的「明确不做」写了「第二刮削源，JavSP / MDCx 多站回退」。由用户决定是否改范围，以及能否提供可用的 JavDB Cookie 或代理。
